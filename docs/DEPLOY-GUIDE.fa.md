# راهنمای قدم‌به‌قدم انتشار ربات

این راهنما برای مالک‌هاست: از خرید سرور تا وقتی ربات اصلی روی تلگرام کار می‌کند. نسخه‌ی فنی و خلاصه‌ی همین مراحل در [`DEPLOY.md`](../DEPLOY.md) است؛ اگر جایی این دو با هم فرق داشتند، `DEPLOY.md` درست است و این فایل باید اصلاح شود.

> **وضعیت فعلی:** فایل‌های `Dockerfile` و `docker-compose.yml` و تنظیم Caddy (برای HTTPS) هنوز ساخته نشده‌اند — بند دوم فاز ۵ در [`ROADMAP.md`](../ROADMAP.md). قدم‌های ۱ تا ۷ را همین الان می‌توانید انجام دهید؛ قدم ۸ به بعد بعد از merge شدن آن PR کار می‌کند.

چرا سرور باید خارج از ایران باشد: [ADR-0002](adr/0002-vps-outside-iran.md) (دسترسی به `api.telegram.org` از ایران بسته است).

## قدم ۰ — قبل از شروع، این‌ها را آماده کنید

- [ ] یک کامپیوتر با ترمینال: در ویندوز **PowerShell**، در مک **Terminal**.
- [ ] یک **مدیر رمز** (Bitwarden، 1Password، KeePassXC) برای هر دو مالک. چند رمز مهم می‌سازیم که اگر گم شوند، اطلاعات انبار و بکاپ‌ها برای همیشه غیرقابل‌خواندن می‌شوند.
- [ ] یک فایل یادداشت موقت برای جمع کردن این مقادیر (بعداً در فایل `.env` می‌روند):

| مقدار                | از کجا                |
| -------------------- | --------------------- |
| توکن ربات اصلی       | قدم ۱                 |
| آیدی عددی دو مالک    | قدم ۱                 |
| یوزرنیم کانال عمومی  | قدم ۱                 |
| آیدی عددی کانال بکاپ | قدم ۱                 |
| IP و رمز root سرور   | قدم ۲ (ایمیل ParsVDS) |
| نام دامنه            | قدم ۳                 |

## قدم ۱ — تلگرام: ربات، کانال‌ها و آیدی‌ها

### ۱٫۱ ربات اصلی (prod)

ربات تست (dev) را برای توسعه نگه دارید؛ برای مشتری‌ها یک ربات جدا بسازید.

1. در تلگرام به `@BotFather` بروید و `/newbot` بزنید.
2. یک نام نمایشی و یک یوزرنیم (باید به `bot` ختم شود) بدهید.
3. توکنی که می‌دهد (شبیه `123456789:AAH...`) را در مدیر رمز ذخیره کنید. **این توکن را به هیچ‌کس ندهید**؛ هر کس داشته باشد ربات را کنترل می‌کند. اگر لو رفت: `/revoke` در BotFather.

### ۱٫۲ آیدی عددی دو مالک

هر دو مالک به `@userinfobot` پیام بدهند؛ عدد `Id` را یادداشت کنید (مثلاً `111111111`).

### ۱٫۳ کانال عمومی

یک کانال عمومی بسازید (برای عضویت اجباری). یوزرنیمش را با `@` یادداشت کنید، مثلاً `@abis_shop`.

### ۱٫۴ کانال خصوصی بکاپ

1. یک کانال **خصوصی** بسازید و هر دو مالک را عضو کنید.
2. برای گرفتن آیدی عددی‌اش: یک پیام از کانال را به `@userinfobot` (یا `@getidsbot`) فوروارد کنید. عددی که با `-100` شروع می‌شود همان آیدی است.

ادمین کردن ربات در کانال‌ها را در قدم ۱۰ انجام می‌دهیم.

## قدم ۲ — خرید سرور (VPS)

از **ParsVDS** (پرداخت تومانی) یک سرور مجازی با این مشخصات بخرید:

| مورد       | مقدار                           |
| ---------- | ------------------------------- |
| لوکیشن     | **آلمان یا هلند** (نه ایران)    |
| سیستم‌عامل | **Ubuntu 24.04**                |
| CPU        | حداقل ۲ هسته                    |
| رم         | حداقل ۲ گیگ                     |
| دیسک       | حداقل ۴۰ گیگ (ترجیحاً SSD/NVMe) |
| IP         | یک IPv4 اختصاصی                 |

بعد از خرید، ParsVDS یک **IP** و **رمز root** می‌دهد. هر دو را در مدیر رمز بگذارید.

موقع خرید از پشتیبانی بپرسید آیا **پنل DNS** هم می‌دهند (برای قدم ۳ لازم است). اگر نه، از DNS رایگان ArvanCloud استفاده می‌کنیم.

---

## قدم ۳ — دامنه و DNS

### ۳٫۱ خرید دامنه

1. در [nic.ir](https://nic.ir) یک شناسه‌ی کاربری (حساب) بسازید.
2. دامنه‌ی `.ir` مورد نظر را ثبت و پرداخت کنید.

### ۳٫۲ تنظیم DNS

ایرنیک خودش رکورد DNS نگه نمی‌دارد؛ فقط می‌گوید «DNS این دامنه کجاست». پس:

1. در پنل DNS (ParsVDS یا ArvanCloud) دامنه را اضافه کنید. دو آدرس **nameserver** به شما می‌دهد (چیزی شبیه `ns1....` و `ns2....`).
2. در پنل ایرنیک، در بخش مدیریت دامنه، همین دو nameserver را وارد کنید.
3. برگردید به پنل DNS و یک رکورد بسازید:
   - نوع: `A`
   - نام: `@` (یعنی خود دامنه)
   - مقدار: **IP سرور**
   - اگر ArvanCloud است: **پروکسی/CDN را خاموش کنید** (ابر خاکستری). Caddy باید مستقیم گواهی بگیرد.

اعمال شدن ممکن است از چند دقیقه تا ۲۴ ساعت طول بکشد. در قدم ۷ بررسی‌اش می‌کنیم؛ لازم نیست منتظر بمانید.

## قدم ۴ — اولین اتصال به سرور (SSH)

SSH یعنی کنترل سرور از راه دور با ترمینال. به‌جای رمز از **کلید** استفاده می‌کنیم که امن‌تر است.

### ۴٫۱ ساخت کلید روی کامپیوتر خودتان (فقط یک بار)

در PowerShell یا Terminal:

```bash
ssh-keygen -t ed25519
```

سه بار Enter بزنید (یا برای امنیت بیشتر یک passphrase بدهید). دو فایل ساخته می‌شود در پوشه‌ی `~/.ssh/`: `id_ed25519` (خصوصی، **هرگز به کسی ندهید**) و `id_ed25519.pub` (عمومی، روی سرور می‌رود).

هر مالک کلید خودش را بسازد.

### ۴٫۲ گذاشتن کلید روی سرور

**مک/لینوکس:**

```bash
ssh-copy-id root@<IP سرور>
```

**ویندوز (PowerShell):**

```bash
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@<IP سرور> "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

بار اول می‌پرسد `Are you sure you want to continue connecting?` → بنویسید `yes`. بعد رمز root را می‌خواهد (موقع تایپ چیزی نشان نمی‌دهد؛ طبیعی است).

### ۴٫۳ ورود

```bash
ssh root@<IP سرور>
```

اگر این بار رمز نخواست، کلید درست نصب شده. از اینجا به بعد دستورها **روی سرور** اجرا می‌شوند.

## قدم ۵ — امن‌سازی سرور

همه‌ی این دستورها روی سرور، به‌عنوان root.

### ۵٫۱ به‌روزرسانی سیستم

```bash
apt update && apt upgrade -y
```

نصب خودکار وصله‌های امنیتی:

```bash
apt install -y unattended-upgrades && dpkg-reconfigure -plow unattended-upgrades
```

(در صفحه‌ای که باز می‌شود `Yes` را انتخاب کنید.)

### ۵٫۲ ساخت کاربر `deploy`

با root کار روزمره نمی‌کنیم. یک کاربر جدا می‌سازیم:

```bash
adduser deploy
```

یک رمز قوی بدهید (در مدیر رمز ذخیره کنید) و بقیه‌ی سؤال‌ها را با Enter رد کنید.

```bash
usermod -aG sudo deploy
```

کلید SSH را به کاربر جدید هم بدهید:

```bash
mkdir -p /home/deploy/.ssh && cp ~/.ssh/authorized_keys /home/deploy/.ssh/ && chown -R deploy:deploy /home/deploy/.ssh && chmod 700 /home/deploy/.ssh && chmod 600 /home/deploy/.ssh/authorized_keys
```

### ۵٫۳ فایروال

فقط SSH و وب (۸۰ و ۴۴۳) باز می‌ماند:

```bash
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw enable
```

سؤال `Proceed with operation` → `y`.

### ۵٫۴ تست ورود با `deploy` (مهم — قبل از قدم بعد)

**ترمینال فعلی را نبندید.** یک ترمینال جدید روی کامپیوتر خودتان باز کنید:

```bash
ssh deploy@<IP سرور>
```

اگر بدون رمز وارد شدید، ادامه دهید. اگر نشد، **قدم ۵٫۵ را انجام ندهید** — ممکن است خودتان را از سرور بیرون بیندازید.

### ۵٫۵ بستن ورود با رمز

در همان ترمینال root:

```bash
nano /etc/ssh/sshd_config
```

این خط‌ها را پیدا کنید (با `Ctrl+W` جستجو کنید)، `#` اولشان را بردارید و مقدار را این‌طور کنید:

```
PasswordAuthentication no
PermitRootLogin no
```

ذخیره: `Ctrl+O` و Enter، خروج: `Ctrl+X`. اگر پوشه‌ی `/etc/ssh/sshd_config.d/` فایلی دارد که `PasswordAuthentication yes` در آن است، آن را هم `no` کنید.

```bash
systemctl restart ssh
```

دوباره از یک ترمینال جدید `ssh deploy@<IP سرور>` را امتحان کنید که مطمئن شوید هنوز وارد می‌شوید.

> اگر روزی کامپیوترتان و کلید را گم کردید: از **کنسول وب** در پنل ParsVDS وارد سرور شوید و کلید جدید را اضافه کنید. برای همین است که هر دو مالک کلید جدا دارند.

## قدم ۸ — دریافت کد و ساخت فایل `.env`

> این قدم و بعدی‌ها بعد از آماده شدن فایل‌های Docker تولید (فاز ۵) کار می‌کنند.

### ۸٫۱ دریافت کد

اگر مخزن عمومی است، همان `git clone https://github.com/Rezaabdollahi7/Abis-bot.git ~/abis` کافی است و به ۸٫۲ بروید. اگر خصوصی است، سرور باید اجازه‌ی خواندن داشته باشد. ساده‌ترین راه **Deploy key** است (فقط‌خواندنی، فقط برای همین مخزن):

1. روی سرور یک کلید جدا برای گیت‌هاب بسازید:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/github_deploy -N ""
```

```bash
cat ~/.ssh/github_deploy.pub
```

2. خروجی را کپی کنید. در گیت‌هاب: مخزن ← **Settings** ← **Deploy keys** ← **Add deploy key**. اسم بدهید (مثلاً `vps`)، متن را بچسبانید، تیک **Allow write access** را **نزنید**، ذخیره.
3. به سرور بگویید برای گیت‌هاب از این کلید استفاده کند:

```bash
printf 'Host github.com\n  IdentityFile ~/.ssh/github_deploy\n  IdentitiesOnly yes\n' >> ~/.ssh/config
```

4. کد را بگیرید:

```bash
git clone git@github.com:Rezaabdollahi7/Abis-bot.git ~/abis && cd ~/abis
```

(سؤال `yes/no` → `yes`.)

### ۸٫۲ ساخت `.env`

```bash
cp .env.example .env && chmod 600 .env
```

سه رمز تصادفی بسازید — این دستور را **سه بار** اجرا کنید و هر خروجی را برای یک مورد بردارید:

```bash
openssl rand -base64 32
```

- اولی ← `ENCRYPTION_KEY`
- دومی ← `BACKUP_PASSPHRASE`
- سومی ← `POSTGRES_PASSWORD` (اگر `/` یا `+` یا `=` داشت، با `openssl rand -hex 24` یکی دیگر بسازید؛ چون داخل `DATABASE_URL` هم می‌رود)

و یکی هم برای webhook:

```bash
openssl rand -hex 32
```

← `WEBHOOK_SECRET`

> ⚠️ **`ENCRYPTION_KEY` و `BACKUP_PASSPHRASE` را همین الان در مدیر رمز هر دو مالک ذخیره کنید.** اگر سرور از بین برود و این دو را نداشته باشید، اطلاعات انبار (اکانت‌هایی که می‌فروشید) و همه‌ی بکاپ‌ها **برای همیشه** غیرقابل‌بازیابی‌اند. این کلید را بعداً عوض نکنید.

فایل را باز کنید:

```bash
nano .env
```

و این‌طور پر کنید (مقادیر نمونه را با مقادیر خودتان عوض کنید):

```
NODE_ENV=production

BOT_TOKEN=<توکن ربات اصلی از قدم ۱٫۱>
WEBHOOK_SECRET=<خروجی openssl rand -hex 32>
PUBLIC_URL=https://<دامنه>
OWNER_TELEGRAM_IDS=<آیدی مالک ۱>,<آیدی مالک ۲>
CHANNEL_ID=@<یوزرنیم کانال عمومی>
BACKUP_CHANNEL_ID=<آیدی کانال بکاپ، با -100 شروع می‌شود>

POSTGRES_PASSWORD=<رمز دیتابیس>
DATABASE_URL=postgres://abis:<همان رمز دیتابیس>@db:5432/abis

ENCRYPTION_KEY=<رمز اول>
BACKUP_PASSPHRASE=<رمز دوم>
```

نکته‌ها:

- در `DATABASE_URL` میزبان **`db`** است (نه `localhost`)؛ اسم سرویس دیتابیس داخل Docker است.
- `HTTPS_PROXY` را روی سرور خارجی **نگذارید**.
- بین `=` و مقدار فاصله نگذارید.

ذخیره: `Ctrl+O`، Enter، `Ctrl+X`.

## قدم ۹ — اجرای ربات

```bash
cd ~/abis && docker compose up -d --build
```

بار اول چند دقیقه طول می‌کشد. سرور هنگام بالا آمدن خودش migrationهای دیتابیس را اجرا و webhook را در تلگرام ثبت می‌کند؛ Caddy هم خودش گواهی HTTPS می‌گیرد.

بررسی:

```bash
docker compose ps
```

همه‌ی سرویس‌ها باید `running` (یا `healthy`) باشند.

```bash
docker compose logs -f server
```

لاگ‌ها را ببینید (خروج: `Ctrl+C`؛ ربات خاموش نمی‌شود). دنبال خطای قرمز یا `Error` بگردید.

تست از کامپیوتر خودتان: آدرس `https://<دامنه>` را در مرورگر باز کنید؛ باید قفل HTTPS داشته باشد.

## قدم ۱۰ — تنظیمات BotFather و کانال‌ها

### ۱۰٫۱ ادمین کردن ربات

- ربات اصلی را **ادمین کانال عمومی** کنید (برای چک کردن عضویت اجباری لازم است). کمترین دسترسی کافی است.
- ربات اصلی را **ادمین کانال بکاپ** کنید با اجازه‌ی **ارسال پیام**.

### ۱۰٫۲ ظاهر ربات

در `@BotFather`، ربات اصلی را انتخاب کنید:

- `/setdescription` — متنی که قبل از Start می‌بینند
- `/setabouttext` — متن کوتاه پروفایل
- `/setuserpic` — لوگو
- `/setcommands` ← بفرستید: `start - شروع`

### ۱۰٫۳ پنل مدیریت (اختیاری)

مدیریت اصلی داخل چت با `/admin` است و پنل وب با `/panel` در مرورگر باز می‌شود. اگر بخواهید پنل به‌صورت Mini App داخل تلگرام هم باز شود: در BotFather ← **Bot Settings** ← **Configure Mini App** ← آدرس `https://<دامنه>/`.

## قدم ۱۱ — تست واقعی قبل از اعلام عمومی

با دو حساب مالک، این‌ها را **روی ربات اصلی** امتحان کنید:

- [ ] `/start` بدون عضویت در کانال → پیام عضویت اجباری می‌آید؛ بعد از عضویت، منو باز می‌شود.
- [ ] `/admin` برای مالک‌ها باز می‌شود و برای یک حساب دیگر نه.
- [ ] کارت بانکی را از منوی ادمین اضافه کنید.
- [ ] یک محصول ارزان + یک قلم انبار اضافه کنید.
- [ ] شارژ کیف پول با مبلغ کم (کارت‌به‌کارت واقعی) → تأیید توسط مالک دیگر → موجودی درست است.
- [ ] خرید → تحویل خودکار → اطلاعات درست به خریدار رسید.
- [ ] یک تیکت باز کنید و جواب دهید.
- [ ] `/panel` را بزنید و لینک در مرورگر باز شود.
- [ ] بکاپ شبانه فردا صبح در کانال بکاپ هست، و **یک بار بازیابی را تست کنید** (قدم ۱۳).

## قدم ۱۲ — به‌روزرسانی ربات (هر بار که کد جدید merge شد)

فقط وقتی تغییر روی `main` merge شده و CI سبز است:

```bash
ssh deploy@<IP سرور>
```

```bash
cd ~/abis && git pull && docker compose up -d --build
```

```bash
docker compose logs --tail=100 server
```

### برگشت به نسخه‌ی قبل (Rollback)

اگر نسخه‌ی جدید خراب بود، شناسه‌ی commit سالم قبلی را پیدا کنید:

```bash
git log --oneline -10
```

```bash
git checkout <شناسه‌ی commit سالم> && docker compose up -d --build
```

بعد از درست شدن مشکل روی `main`، برای برگشتن به حالت عادی:

```bash
git checkout main && git pull && docker compose up -d --build
```

> migrationهای دیتابیس فقط رو به جلو هستند. اگر migration خراب اجرا شد، برگشتن کد کافی نیست — به توسعه‌دهنده خبر دهید (یا آخرین بکاپ را بازیابی کنید).

## قدم ۱۳ — بکاپ و تست بازیابی

ربات هر شب از دیتابیس بکاپ می‌گیرد، با `BACKUP_PASSPHRASE` رمزنگاری می‌کند و در کانال خصوصی می‌فرستد.

**بکاپی که تست نشده، بکاپ نیست.** یک بار هنگام راه‌اندازی و بعد ماهی یک بار، روی کامپیوتر خودتان (نه سرور اصلی) بازیابی را امتحان کنید:

1. فایل بکاپ را از کانال دانلود کنید.
2. با یک دیتابیس محلی (`pnpm dev:db` در پوشه‌ی پروژه):

```bash
gpg --decrypt backup.sql.gpg | docker compose -f docker-compose.dev.yml exec -T db psql -U abis abis
```

(`BACKUP_PASSPHRASE` را می‌خواهد.) اگر جدول‌ها و داده‌ها آمدند، بکاپ سالم است.

## عیب‌یابی رایج

| مشکل                                   | علت محتمل / کار                                                                                                    |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `ssh: connect ... timed out`           | IP اشتباه، سرور خاموش، یا فایروال SSH را بسته. از کنسول وب ParsVDS وارد شوید و `ufw status` را ببینید.             |
| `Permission denied (publickey)`        | کلید روی سرور نیست یا از کامپیوتر دیگری وصل شده‌اید. از کنسول وب کلید را به `authorized_keys` اضافه کنید.          |
| ربات جواب نمی‌دهد                      | `docker compose logs server` را ببینید. اغلب: توکن اشتباه، `PUBLIC_URL` اشتباه، یا DNS هنوز به سرور اشاره نمی‌کند. |
| گواهی HTTPS گرفته نمی‌شود              | DNS (قدم ۷) درست نیست، پورت ۸۰/۴۴۳ بسته است، یا CDN آروان روشن مانده. `docker compose logs caddy`.                 |
| خطای اتصال به دیتابیس                  | رمز در `POSTGRES_PASSWORD` و `DATABASE_URL` یکی نیست، یا میزبان `localhost` نوشته شده به‌جای `db`.                 |
| عضویت اجباری همیشه «عضو نیستی» می‌گوید | ربات ادمین کانال عمومی نیست یا `CHANNEL_ID` غلط است.                                                               |
| دیسک پر شد                             | `docker system prune` (ایمیج‌های قدیمی را پاک می‌کند؛ دیتابیس را پاک نمی‌کند).                                     |

## خلاصه‌ی چیزهایی که باید امن نگه دارید

| چیز                    | اگر گم شود                                    | اگر لو برود                                       |
| ---------------------- | --------------------------------------------- | ------------------------------------------------- |
| `ENCRYPTION_KEY`       | **انبار و بکاپ‌ها برای همیشه از دست می‌روند** | اطلاعات انبار قابل‌خواندن می‌شود                  |
| `BACKUP_PASSPHRASE`    | بکاپ‌ها بی‌استفاده می‌شوند                    | هر کس فایل بکاپ را داشته باشد می‌خواندش           |
| `BOT_TOKEN`            | از BotFather دوباره بگیرید                    | فوراً `/revoke` در BotFather و `.env` را عوض کنید |
| کلید SSH خصوصی         | از کنسول وب ParsVDS کلید جدید اضافه کنید      | کلید را از `authorized_keys` سرور حذف کنید        |
| رمز root / پنل ParsVDS | بازیابی از طریق ParsVDS                       | فوراً عوض کنید                                    |
